# R4b: installer and resumable uninstall foundation

Contract: identity R4 specification, including PR #45 (08644c1), #46 (88f19af)
and #47 (b3b0141, approved 29f7755). This is product PR 4b only. Both engines
remain byte-pinned by engines.lock.json and are unchanged.

## Production boundary

The production release key is empty. Every install mode refuses with
`trajecta: no trusted release key configured` before root/store mutation.
Foundation artifacts also refuse in production. There is no custom environment,
CLI or configuration switch for trust. No signing key, release workflow,
release environment, publishing or tag is created by this work.

Tests substitute only an ephemeral in-memory public anchor and foundation
allowance through a test-only `--import` loader; the private key never leaves
its test process. release.json signatures cover exact bytes, including the
exact packed MANIFEST SHA-256. The extractor authenticates the complete file
inventory and rejects unsafe metadata before creating staging.

The reviewed install.sh/install.ps1 bootstrap embeds the same root/lock kernel,
not downloaded helper code. The small shell/PowerShell control path probes Node;
POSIX execs it and PowerShell starts it and waits without filesystem effects.
The inline Node verifier owns the lock and imports only the digest-checked
extractor and verified staged code. Kernel embedding is generated by
`tools/bootstrap-build.ts` and checked byte-for-byte on both supported Nodes.
Download and check the script's published out-of-band SHA before running it;
there is no release bootstrap or published hash claim in this foundation PR.

## Runtime and ownership

The CLI supports install, doctor, install --rollback, install --break-lock,
uninstall, uninstall --version, uninstall --status and uninstall --resume.
The bootstrap's --resume-uninstall imports a freshly verified staged resume
entry; it never executes .uninstall/node. Root/release/database/profile/work
paths can be supplied explicitly. Tests always isolate data and profile roots.

Only the lock-owner process writes root or store state. runStagedInstall calls
an explicit exported installStaged entry of verified code. That entry checks
its own PID/token and never acquires another lock. The extractor, identity
public init and ledger writes have the same owner PID, proved by write trace.
Node handoff precedes acquisition. Version probes are read-only children.
The engine dispatcher remains argv plus import, with no product error wrapper.

Lock records are fsynced and link-published. Stale removal wins an exclusive
identity claim before its final re-read/unlink. Live locks refuse; unreadable
or remote records require the typed TTY decision. Claim n+1 follows only a
provably dead local claimant or the explicit remote-human assertion. Holders
clean only foreign-identity exact-pattern regular claim files. No recover mutex.

The two-line current pointer changes in one rename. The plan uses actual
Phase-A bytes and records only staging-created directories, never an existing
unowned directory. Ledger convergence requires actual bytes to match expected
hashes. A plan does not confer ownership by itself. The locally generated plan
control receipt is computed from the canonical writer bytes, and an existing
receipt is never silently replaced. Bootstrap intent records the originally
observed absence so an effect/ledger crash converges; it never owns a store.
Identity uses public init only when absent. Work is left lazy-empty and is read
through public list(). Doctor reads existing stores only; legacy-v4 refusal
remains frozen.

Full uninstall authenticates and copies engine-free product code before intent,
prints an externally anchored verifier, then sets uninstalling. It deletes
hash-matching owned files and empty owned directories, current version last.
Changed/unlisted controls and nested content stay and are reported. Shared
removal waits for zero versions. The update-state decision precedes final
control removal; non-TTY, --yes and declining keep it. Stores, profiles and
client configurations are never removed.

Terminal recovery cleanup is shared by finalization, fresh install and fallback:
authenticate every remaining product file via signed release/MANIFEST; unlink
node then DIGESTS; unlink authenticated product files and empty implied dirs;
unlink MANIFEST, signature, release; remove the empty recovery directory.
Missing product files are allowed only here. Unknown/altered product code or
missing signed metadata while code remains refuses before deletion. The five
named inert files never execute or independently establish trust. Unexpected
names and symlinks are retained. All recovery and version deletion uses individual
unlink/rmdir calls, with no recursive removal. Recursive removal is confined to
owned abandoned/per-run staging under the lock.

## Gates and scope split

The unchanged 4a gates remain: 190 identity CLI cases (189 frozen plus version),
125 untouched work tests, direct/product byte-exact pairs, real-engine signal/PTY,
readable-v4, offline default profile, source fences and deterministic artifacts.

4b adds signature/malformed payload and compatibility gates; bootstrap/doctor
authority differential and filesystem/native SQLite trace; real kill/re-entry
at A/B/C and every named terminal boundary, every recovery product unlink and
version file unlink; rollback, retention/co-tamper and lost printed anchor;
no-Node refusal and real cross-Node handoff; 200 rounds/four live contenders plus
adversarial claim schedules. The historical Windows/Node22 LockTimeout remains
work issue #12, root cause unconfirmed; the concurrency gate references it and
does not alter or excuse either engine's comparator.

All run on Linux/macOS/Windows × Node 22/24; exact artifacts are compared across
all six. Each job also supplies the alternate Node for a real pre-lock handoff.
OS-specific real bootstrap tests skip only their opposite OS. No gate/comparator
is loosened, no --exclude, and no engine test is removed.

Deferred explicitly:

- **4c M2/M3/M5:** OS-native wrappers/user-bin, real launcher clean install and
  modified-launcher acceptance; plugin zip/render/copy effects and their ledger
  crash points; wrapper/MCP no-Node diagnostics and Windows console/MCP acceptance;
  plugin K1–K6 and a full native-wrapper/plugin clean-install claim.
- **4d M2/M3 additions:** update index/freshness/rotation/sequence, remembered
  rotation after rollback, reset/floor/state transitions, downgrade/same-version,
  update compatibility refusal and product TTY migration. 4b only handles the
  owner-authorized uninstall exception and preservation of update-state.
- **Release/M8/Q9:** real key consent, out-of-band publication, release workflow,
  release artifact, signing, tags, publishing and product cutover.

This foundation does not claim complete clean-install M3 without 4c.
