# Remaining R4c native M5 implementation plan

**Goal:** Prove the eight remaining gates with native, exact-head evidence, or
retain a concrete STOP. The accepted guard fix at `200152e` stays unchanged.

**Architecture:** Test-only Windows fixtures use a locally compiled Microsoft
.NET console helper, an isolated disposable VHD when available, and the actual
installed product and engine entries. Tests record raw bytes before assertions.
Existing POSIX signal and MCP tests remain unchanged; extra receipts expose
their native outcomes. Production code changes require a reproduced defect.

**Spec:** Identity R4 product-cutover §§13.3, 13.5, 13.7–13.8, blob
`f7a257ef0c71cb138167daca956b0588cf8b746f`; Aux's eight-gate request.

## Global constraints

- Node 22 and 24, native Windows; relevant POSIX gates on macOS and Linux.
- No engine changes, signing, release, tags, real stores/configs/plugins or
  comparator relaxation. Empty production anchor; only in-memory test keys.
- Every fixture, executable, VHD and receipt stays inside this checkout.
- No service restart, global 8.3 setting change or silent policy emulation.
- Pre-warm the identical pinned PowerShell before exact whole-tree baselines.
- A controlled error record, missing executable or ACL denial does not prove
  real 8.3-disabled or AppLocker/WDAC acceptance.

## Review focus

- Disabled short names must be verified on the actual volume and actual file.
- A canary must be shown capable of running before proving it was not selected.
- A descendant must really hold both redirected pipe handles past parent death.
- Long-root success must include real install and actual engine MCP framing.
- Console evidence must use a real Windows console, not `child.kill(SIGINT)`.
