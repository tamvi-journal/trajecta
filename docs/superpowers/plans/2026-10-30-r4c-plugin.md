> Execution: implement directly in this session, following the assigned scope.

**Goal:** native launchers, profile-specific product plugins, ownership convergence,
and bounded extraction, with exact M2/M3/M5 evidence.

**Architecture:** templates produce immutable shared routing wrappers; Node's `mcp`
verb applies the explicit recipe and delegates through `engines.ts`. Phase A builds
the exact effects, Phase C publishes them and records their actual hashes. External
user-bin management is only an atomic no-replace hard link and report-only receipt.

## Constraints and review focus

- Preserve both engine pins, all existing exact comparators and gates.
- Empty production trust anchor; no signing, release environment/workflow, tags or publishing.
- Every writer under the install lock is the owner's PID; no nested root lock.
- Root injection occurs once as a single quoted assignment; diagnostics are static printf formats.
- Wrappers reject malformed pointers before Node/product execution; sentinel wins over Node absence.
- External stub publication never replaces, deletes or creates directories outside root.
- Two plugins/default recipes remain independent; Windows unsafe fields refuse before writes.
- Every runtime command uses isolated data/profile/home roots in tests.
